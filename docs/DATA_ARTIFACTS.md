# Data artifacts (not in git)

The repository contains **application code, migrations, and small test fixtures** only. Heavy or environment-specific data is excluded via `.gitignore` and distributed separately (cloud storage, internal share, etc.).

## What stays in git

| Path | Purpose |
|------|---------|
| `infra/migrations/*.sql` | Postgres schema |
| `services/ingest/fixtures/*.json` | Small websocket/API samples for tests |
| `analytics/**/README.md`, `analytics/research/*.py` | Docs and runbook scripts |
| `.env.example` | Non-secret configuration template |

## What does not stay in git

| Path / pattern | Typical size | How devs get it |
|----------------|--------------|-----------------|
| `target/`, `target-*/` | GB | `cargo build` locally |
| `python/data/`, `data/`, `**/*.parquet` | MB–GB | Backfill, cloud bundle, or live ingest |
| Postgres database `hyperion` | GB | `pg_restore` from dump, or empty DB + live scoop |
| `analytics/research/live_scoop_logs/` | MB | Created by `restart-live-scoop.ps1` |
| `analytics/research/*_audit_*.md`, `copy_backtest/`, caches | MB | Regenerated by scripts or copied from bundle |
| `.env` | — | Copy from `.env.example` |

## Recommended shared data bundle layout

When you publish a cloud archive for the team, use a layout that mirrors local paths so restore is copy-paste:

```text
hyperion-shared-data-YYYYMMDD/
├── README.txt                 # manifest: git commit hash, dump timestamps
├── postgres/
│   └── hyperion.dump          # pg_dump -Fc -d hyperion
├── parquet/                   # optional historical lake
│   └── fills/
│       └── year=YYYY/month=MM/day=DD/*.parquet
└── analytics/
    ├── research/
    │   ├── hyperliquid_leaderboard_cache.json
    │   └── copy_backtest/     # optional exported tapes
    └── ...
```

### Restore Postgres (Scoop or local Postgres)

```powershell
# From hyperion/ with Postgres running and empty DB (or drop/recreate hyperion)
$pg = "$env:USERPROFILE\scoop\apps\postgresql\current\bin"
& "$pg\pg_restore.exe" -U postgres -d hyperion --clean --if-exists ..\hyperion-shared-data-*\postgres\hyperion.dump
```

Fresh devs without a dump: run migrations and live scoop (see `docs/local-development.md`).

```powershell
powershell -ExecutionPolicy Bypass -File infra/scripts/migrate.ps1
powershell -ExecutionPolicy Bypass -File infra/scripts/restart-live-scoop.ps1
```

### Restore Parquet (optional)

```powershell
# Default PIPELINE_DATA_DIR for CLI is python/data when run from python/
Copy-Item -Recurse ..\hyperion-shared-data-*\parquet\* python\data\
```

Or set `PIPELINE_DATA_DIR` in `.env` to point at `shared-data/parquet` after unpacking into `hyperion/shared-data/`.

### Restore analytics caches (optional)

```powershell
Copy-Item -Recurse ..\hyperion-shared-data-*\analytics\research\* analytics\research\
```

## Local-only directories (created automatically)

| Directory | Created by |
|-----------|------------|
| `analytics/research/live_scoop_logs/` | `infra/scripts/restart-live-scoop.ps1` |
| `python/data/` | `hyperion-pipeline backfill-wallet --parquet` |
| `shared-data/` | Manual unpack of cloud bundle (gitignored except README) |

## Publishing a new bundle (maintainers)

1. Note the git commit SHA in the bundle README.
2. `pg_dump -Fc -U postgres -d hyperion -f hyperion.dump`
3. Include `python/data/` and any `analytics/research` caches the team relies on.
4. Exclude `target/`, `.env`, and `live_scoop_logs/` (reproducible locally).

## Verify nothing heavy is staged

```powershell
git status
git check-ignore -v analytics/research/live_scoop_logs/ingest_*.log
git check-ignore -v target/debug/hyperion-ingest.exe
```
